## 8. Agent runtime

### 8.1 Context injection (`backend/mcp_bridge.py`)
A `MemoryContext(tenant_id, user_id, agent_id, session_id)` object is bound per agent turn. The bridge:
1. Calls MCP `list_tools()`. For the agent's role it keeps only allowlisted tools (Section 7.4).
2. Builds `ToolSpec`s by **removing** `tenant_id`, `user_id`, `agent_id`, `session_id` from each input schema, then applying `simplify_schema`.
3. On every call: takes the LLM's args, **drops any context-field keys the LLM supplied** (emit a `warning` event if it did), then adds the bound context fields and calls the MCP tool.
4. Parses the envelope JSON; returns it to the loop. Before the envelope goes back to the LLM, **delete `evidence.graph`** (the UI event still gets the full envelope).
Test: a call with LLM args `{"tenant_id": "globex", "query": "x"}` executes against the bound tenant and emits a `warning` (G13).

### 8.2 LLM adapter (provider-neutral)

**Rule: `agent_live.py` must never import `google.genai` or `anthropic`.** It only uses the types below. All chat-provider code lives in `backend/llm/`. (The only other file allowed to import `google.genai` is `memory_core/embedder.py`, for embeddings.)

Files:
```
backend/llm/__init__.py        # make_session(...) factory
backend/llm/base.py            # dataclasses + LLMSession Protocol
backend/llm/schema.py          # simplify_schema(), assert_simple_schema()
backend/llm/gemini_client.py   # GeminiSession (REQUIRED)
backend/llm/anthropic_client.py# AnthropicSession (OPTIONAL, skip by default)
backend/llm/fake_client.py     # FakeSession (scripted, for tests)
```

`base.py` (write exactly these names):
```python
@dataclass
class ToolSpec:   name: str; description: str; input_schema: dict      # simple JSON Schema
@dataclass
class ToolCall:   id: str; name: str; args: dict                        # id is generated by us (uuid4 hex[:8])
@dataclass
class ToolResult: call_id: str; name: str; content: dict; is_error: bool = False   # content = parsed MCP envelope
@dataclass
class LLMTurn:    text: str; tool_calls: list[ToolCall]                 # text may be "" ; tool_calls may be []

class LLMSession(Protocol):
    async def send_user(self, text: str) -> LLMTurn: ...
    async def send_tool_results(self, results: list[ToolResult]) -> LLMTurn: ...
```
Each session object **owns its own conversation history** internally. The agent loop never builds provider messages.

Factory: `make_session(provider: str, system: str, tools: list[ToolSpec]) -> LLMSession`. `provider` comes from env `LLM_PROVIDER` (`gemini` default).

### 8.2.1 Tool schema rules (so Gemini accepts every tool)
1. Pydantic models for tool inputs must **not** use `Optional[...]` or unions. Use a default value instead (`max_hops: int = 3`).
2. `simplify_schema(schema)` must: inline every `$ref`/`$defs`; delete `title` and `default` keys; convert `anyOf: [X, {type: null}]` to `X`; keep only `type`, `properties`, `required`, `enum`, `items`, `description`, `minimum`, `maximum`.
3. `assert_simple_schema(schema)` raises if any other key (including `anyOf`, `oneOf`, `allOf`, `$ref`, `$defs`) remains.
4. Test (`tests/test_schema_simple.py`): list all MCP tools, simplify each schema, call `assert_simple_schema`. This test must pass before any Gemini call is attempted.
5. Every tool description must contain two sentences starting `Use when:` and `Do not use when:`.

### 8.2.2 GeminiSession (REQUIRED). Implementation recipe

**Do not rely on memory for SDK names. In T10, print the real field names from the installed SDK (see T10) and fix this recipe if any name differs; log differences in `DECISIONS.md`.**

Facts (verified from Google docs):
- Package: `google-genai`. Import: `from google import genai` and `from google.genai import types`.
- Model id: `gemini-3.8-flash`. Thinking levels: `low`, `medium`, `high`. `minimal` is not supported and returns an error. Never set `thinking_level` and `thinking_budget` together.
- Gemini 3 **requires thought signatures to be sent back** during function calling. If you append the model's **entire response content object unchanged** to the history, the SDK handles signatures. If you rebuild, trim or "clean" the model's content, the API returns a 400 error ("function call ... is missing a thought_signature").
- Function declarations accept JSON Schema through `parameters_json_schema`.
- Automatic function calling must be **disabled** (we run our own loop through MCP).

Recipe:
```python
from google import genai
from google.genai import types

class GeminiSession:
    def __init__(self, api_key, model, thinking_level, system, tools):
        self.client = genai.Client(api_key=api_key)
        self.model = model
        decls = [types.FunctionDeclaration(name=t.name, description=t.description,
                                           parameters_json_schema=t.input_schema) for t in tools]
        self.config = types.GenerateContentConfig(
            system_instruction=system,
            tools=[types.Tool(function_declarations=decls)],
            automatic_function_calling=types.AutomaticFunctionCallingConfig(disable=True),
            thinking_config=types.ThinkingConfig(thinking_level=thinking_level),
        )
        self.contents: list[types.Content] = []   # full history, owned by this object
        self._pending: list[ToolCall] = []        # calls from the last model turn, in order

    async def send_user(self, text):
        self.contents.append(types.Content(role="user", parts=[types.Part.from_text(text=text)]))
        return await self._generate()

    async def send_tool_results(self, results):
        # one Content, role "user", one function_response Part per call, SAME ORDER as the calls
        parts = [types.Part.from_function_response(name=r.name, response=({"error": r.content} if r.is_error else {"output": r.content}))
                 for r in results]
        self.contents.append(types.Content(role="user", parts=parts))
        return await self._generate()

    async def _generate(self):
        resp = await self.client.aio.models.generate_content(model=self.model, contents=self.contents, config=self.config)
        content = resp.candidates[0].content
        self.contents.append(content)             # VERBATIM. Never edit this object.
        text = "".join(p.text for p in content.parts if getattr(p, "text", None) and not getattr(p, "thought", False))
        calls = [ToolCall(id=uuid4().hex[:8], name=p.function_call.name, args=dict(p.function_call.args or {}))
                 for p in content.parts if getattr(p, "function_call", None)]
        return LLMTurn(text=text, tool_calls=calls)
```
Rules for this class:
1. **Never** modify, filter, reorder or drop parts of `content` before appending it to `self.contents`.
2. If the model returns several function calls in one turn, the loop must run **all** of them and send **all** results in **one** `send_tool_results` call, in the same order.
3. Wrap `generate_content` in a retry helper: up to 3 attempts, exponential backoff (1s, 2s, 4s) on HTTP 429 and 5xx. Do not retry 400 errors; raise `LLMError` with the message.
4. Add a per-call timeout of 60 s.
5. Do not set `temperature` (leave the default) unless T10 shows unstable tool calls; if you change it, log it in `DECISIONS.md`.
6. `response` from `from_function_response` must be a dict. Our `content` is already a dict (the parsed MCP envelope). Wrap it as shown (`output` / `error` keys).
7. Read the API key from env `GEMINI_API_KEY`. Never print it or commit it.


### 8.2.3 Extra hardening for a fast, lower-tier model
Add these to `prompts.py` text and to the loop:
1. Each system prompt contains the numbered **playbook for its role** (Section 8.6). The model fills in arguments; it does not invent the workflow.
2. System prompt states: "Call one tool at a time unless two calls are independent."
3. System prompt states: "IDs must be copied exactly from tool results."
4. If the model's first turn has no tool call, send one corrective message once: "You must start by calling a tool as your playbook says."
5. If a tool returns `NOT_FOUND`, the loop adds the hint "Check the ID spelling against previous tool results."


### 8.3 Agent turn loop (`backend/agent_live.py`), provider-neutral
`run_agent_turn(ctx, role, agent_name, input_text, emit) -> AgentTurnResult(messages, handoff_created: str|None)`

```
tools = bridge.tools_for(role)                       # ToolSpecs, context fields removed
session = make_session(provider, system_prompt(role, agent_name), tools)
turn = await session.send_user(runtime_block(ctx) + input_text)
calls_made = 0; seen = Counter(); handoff_created = None
while True:
    if turn.text.strip():
        save + emit message(role="agent", agent_id=ctx.agent_id, text=turn.text)   # all agent text is shown to the user
    if not turn.tool_calls: break
    results = []
    for call in turn.tool_calls:
        calls_made += 1
        if calls_made > 10: emit error(recoverable=false); break out
        key = (call.name, json.dumps(call.args, sort_keys=True)); seen[key] += 1
        if seen[key] > 2: emit error(recoverable=false); break out
        emit tool_call(call without context fields)
        envelope = await bridge.call(ctx, call.name, call.args)
        emit memory_visit / tool_result / and the specialised events of Section 8.8 built from the envelope
        if call.name == "create_handoff" and envelope.ok: handoff_created = envelope.data.handoff_id
        results.append(ToolResult(call.id, call.name, strip_evidence_graph(envelope), is_error=not envelope["ok"]))
    turn = await session.send_tool_results(results)
return AgentTurnResult(...)
```
Rules: tool errors go back to the model as `ToolResult(is_error=True)` and never crash the loop; the specialised events (`fact_update`, `handoff`, `procedure_event`, `task_event`, `session_closed`) are built **by code from the envelope**, never from model text; numbers in `tool_result.summary` are built by code.

### 8.4 Crew runner (`backend/crew.py`)
```
async def run_turn(ctx, user_text, emit):
    append_message(ctx.session_id, role="user", text=user_text); emit message(user)
    agent = read session.current_agent                       # persisted in the graph
    emit agent_active(agent)
    result = await run_agent(ctx.with_agent(agent), user_text)   # mock or live (AGENT_MODE)
    hops = 0
    while result.handoff_created and hops < 2:
        hops += 1
        target = handoff target agent id (read from the Handoff node)
        emit agent_active(target)
        result = await run_agent(ctx.with_agent(target), "A handoff is waiting for you. Start with get_pending_handoffs.")
    emit final
```
The session's `current_agent` is updated in the graph by `accept_handoff`, so a later user message in the same session goes to the specialist. A **new session** always starts with `agent-triage`.

### 8.6 Prompts (`backend/prompts.py`, write in full)
Common rules for every role:
1. "You are `<agent name>` for a customer-support team. Your only knowledge about the customer and past events comes from the memory tools."
2. "Never state a fact, date, plan, preference or past event that a tool did not return."
3. "Anything you write is shown to the customer. Do not narrate your tool use. Keep replies short."
4. "Never ask the customer to repeat information that memory already has."
5. "Node IDs and tool arguments must be copied exactly from tool results. Call one tool at a time unless two calls are independent."
6. "Never mention other customers or other companies."
**Triage playbook:** (1) `get_user_profile`; (2) `recall_memory` with the customer's message; (3) use relevant episodes and facts naturally in your reply; (4) if the issue is billing or a refund, use topic `topic-billing`; if it is VPN or login, use `topic-vpn`; then `route_to_specialist` and `create_handoff`; (5) if the customer states a new plan, preferred channel or city, call `remember_fact`; (6) if you resolve it yourself, reply and call `close_session`.
**Specialist playbook:** (1) `get_pending_handoffs`; (2) `accept_handoff`; (3) read the bundle; (4) `find_procedure` and follow its steps; (5) tell the customer the result; (6) `record_procedure_outcome`; (7) `complete_handoff`; (8) `close_session`.
If a tool returns `FORBIDDEN`, do not retry; if `CONFLICT`, re-read state once and decide.

### 8.7 REST API (`backend/main.py`)
Auth: header `X-API-Key`. The key maps to exactly one tenant (env `TENANT_KEYS`). Every route under `/t/{tenant}/...` must match the key's tenant: missing key gives 401; mismatch gives **403** (G13). Admin routes need header `X-Admin-Key` equal to env `ADMIN_KEY` (default `admin-demo-key`). `tenant` is validated with the tenant-id regex before any DB access.

| Endpoint | Behavior |
|---|---|
| `GET /health` | `{ok:true, tenants:[...]}` (no auth) |
| `GET /t/{tenant}/users` | users of the tenant |
| `POST /t/{tenant}/sessions` | body `{user_id, scenario?}` creates a session (`current_agent=agent-triage`), returns `{session_id}`; with `scenario` uses the scenario's ids/text and starts the run in the background |
| `POST /t/{tenant}/sessions/{sid}/messages` | body `{text}`; runs `crew.run_turn` in the background; returns `{turn_id}` |
| `GET /t/{tenant}/sessions/{sid}/stream` | SSE (replays buffered events, then live; closes after `final` or non-recoverable `error`) |
| `GET /t/{tenant}/sessions/{sid}/messages` | persistent history (oldest first) |
| `POST /t/{tenant}/sessions/{sid}/close` | body `{outcome, summary?}` (runs consolidation) |
| `GET /t/{tenant}/users/{uid}/graph` | bounded memory subgraph for the UI (Section 4.6): `{nodes:[{id,label,props}], edges:[{id,source,target,type}]}` |
| `GET /t/{tenant}/users/{uid}/facts?include_history=bool` | semantic memory |
| `GET /t/{tenant}/users/{uid}/episodes` | episodic memory (ACTIVE and ARCHIVED, with status) |
| `GET /t/{tenant}/procedures` | procedural memory with `successes`, `failures`, `status` |
| `GET /t/{tenant}/tasks`, `GET /t/{tenant}/handoffs` | coordination state |
| `GET /t/{tenant}/isolation-check` | runs the isolation checks of G13 against the *other* tenant; returns `[{name, passed, detail}]` |
| `POST /admin/reset` | re-seed all tenants |
| `POST /admin/load-test` / `GET /admin/load-test/stream` | start the load test (G15) and stream `load_progress` / `load_result` |
| `GET /replays/{scenario}` | serves `replays/<scenario>.jsonl` |

`GET /graph`-style endpoints never return `embedding` fields.

### 8.8 SSE event contract
Envelope: `{"seq": int, "ts": "ISO", "type": "<below>", "data": {...}}`; SSE `event:` equals `type`. Context fields never appear in `tool_call.args`.

| type | data |
|---|---|
| `session_started` | `{session_id, user_id, mode}` |
| `message` | `{role, agent_id, text, seq}` |
| `agent_active` | `{agent_id, role}` |
| `tool_call` | `{call_id, agent_id, tool, args}` |
| `memory_visit` | `{call_id, kind, node_ids, edge_keys}` (**from the tool envelope only**) |
| `tool_result` | `{call_id, ok, summary, query_ids, ms}` |
| `recall_result` | `{episodes:[{id, score, components}], fact_ids, procedure_ids}` |
| `fact_update` | `{action, fact_id, old_fact_id, predicate, object}` |
| `handoff` | `{handoff_id, status, from_agent, to_agent, carries}` |
| `procedure_event` | `{procedure_id, kind ('outcome'\|'promoted'), detail}` |
| `task_event` | `{task_id, status, agent_id}` |
| `session_closed` | `{episode_id, importance, facts_changed, promoted}` |
| `isolation_check` | `{name, passed, detail}` |
| `load_progress` | `{phase, done, total, ops_per_s}` |
| `load_result` | `{checks:[{id, passed, detail}], latency:{p50, p95, p99}, ops, seconds}` |
| `warning` | `{message}` |
| `error` | `{message, recoverable}` |
| `final` | `{session_id, summary}` |
